# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键；来源不全的组会整体列在「待补清单」，并给出组内全部原始记录键与源行号。
3. 修复来源文件，重新上传并执行。新内容形成新批次，待补组只在新批次恢复计算和签发；历史批次与已签发依据保持原样。
4. 完整组对账无差异时可照常签发，不必等整月全部重传；待补组随新批次补齐后再签发。对仍有业务差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

同一份来源重复执行不会新建批次，也不会重复生成待补项，避免丢失记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
