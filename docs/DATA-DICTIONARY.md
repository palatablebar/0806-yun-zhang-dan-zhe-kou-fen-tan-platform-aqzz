# 字段与业务定义

输入编码 UTF-8，允许 BOM。首行必须匹配样例列顺序。记录键和业务组保留原始字符串。`kind` 允许 usage, pool。说明列 `note` 可以跨行，限制 200 字。

业务字段按 `usage_units`、`discount_cents`、`cap_cents` 排列。数字接受非负整数、全角数字和完整千分位。空串、短横线、N/A、NULL 与未知为缺值。无关字段用 0 占位。

金额以分为最小单位。归集正用量，以最大余额法补齐尾分。同余数时按记录键排序。账户额度不足退回复核。

## 组级结算

采信之后按业务组整体判断来源是否完整。一个组只要有一条隔离行（冲突、缺值、列数异常等），整组都不进入归集与分摊，统一列入 `supplement` 待补清单；清单保留该组全部原始记录键（`records`）、坏行记录键（`rejected_records`）、源行号（`lines`）与原因码。组内已采信的记录仍计入对账总量，但随组暂扣，不能单独签发。

完整组照常计算并可签发，不受其他待补组影响。待补组的折扣余额记入 `withheld_discount_cents` 单独暂扣，不分配给任何其他组。

重复回放（同一记录键、内容完全一致）没有丢失内容，不产生待补项，只作为忽略行计数。补正来源后重新上传会形成新批次（按内容摘要区分），待补组只在新批次恢复签发；此前签发的批次与证据保持原样。

`incoming.csv` 包含四个业务组，第二组提供不同边界，第三组触发业务拒收，第四组需要核对。另含重复表头、冲突记录、重复回放与错误列数。`ready.csv` 含可以签发的两个组。
